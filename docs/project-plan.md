# 프로젝트 계획서 초안

버전 0.2 · 작성일 2026-10-25 · 갱신일 2026-10-26 · 소프트웨어공학 1분반 10팀

이 문서는 중간 발표 준비를 위한 협업용 초안이다. 실제 데이터 검증과 팀 검토 후 제출용 계획서로 정리한다.

## 배경과 목적

부산의 청년 프로그램을 찾을 때 사용자는 여러 공고에서 대상과 일정을 개별적으로 확인해야 한다. 본 프로젝트는 사용자가 자연어로 원하는 조건을 제시하면 실제 공공데이터에서 후보를 찾고, 조건에 맞는 근거와 확인되지 않은 항목을 함께 보여주는 서비스를 목표로 한다. 이러한 불편의 빈도와 기존 서비스 대비 효과는 사용자 시나리오 검토를 통해 보완할 예정이다.

## 대상 사용자와 대표 상황

부산에서 교육·문화·취업 준비 등 참여 기회를 찾는 청년을 대상으로 한다. 예를 들어 사용자가 “이번 달에 신청할 수 있는 취업 준비 프로그램을 찾아줘”라고 질문하면, 시스템은 기간과 관심 분야를 추출하고 실제 데이터에서 확인 가능한 조건으로 후보를 찾는다. 이용 자격을 확인할 수 없는 경우 대상 여부를 확정하지 않는다.

## 범위 제안

필수 기능 후보는 자연어 검색, 조건 기반 추천, 프로그램 비교이다. 상세 정보에는 데이터 출처와 수집 시점을 함께 제공한다. 이 후보는 API 실제 응답을 확인한 뒤 확정한다. 기능별 입력·출력·검증 기준은 요구사항명세서에서 정의한다.

로그인, 장기 사용자 프로필, 실제 신청·결제·예약, 자체 공고 작성, 실시간 잔여 정원 보장은 초기 범위에서 제외한다. VLM 포스터 분석과 지도 연동은 추가 기능 후보이다. LLM을 사용하므로 초기 범위에 VLM을 필수로 포함하지 않는다.

## 데이터와 AI 활용

부산광역시 청년지원프로그램 정보 API를 실제 호출해 전체 1,000건과 12개 필드를 확인했다. 10월 26일이 신청기간에 포함되는 원본 레코드는 96건이며 실제 접수 여부를 보장하지 않는다. 상세 수치와 원천 모집 상태 필터의 불일치는 데이터 검증 기록에 정리했다. 검색·추천·비교를 초기 범위로 제안하며 전용 필드가 없는 비용·주소 기반 검색은 포함하지 않는다.

LLM은 자연어 조건 추출과 검증된 결과의 설명에 사용한다. 실제 데이터 검색, 날짜 해석 검증, 조건 비교, 후보 정렬과 출처 연결은 애플리케이션이 수행한다. 생성된 프로그램명·날짜·연락처를 공식 사실로 사용하지 않는다.

## 개발 과정과 역할

1. 데이터 검증과 사용자 문제 정리
2. 요구사항·유스케이스·인수 기준 작성
3. 아키텍처와 컴포넌트 설계
4. 기능별 구현과 PR 검토
5. 단위·통합·시스템 테스트 및 결과 기록

역할은 README의 책임 분담을 따른다. 팀원 3·4는 분석·검증 산출물을 직접 보완하고 발표자료 준비를 주도한다. 실명·학번·GitHub 아이디와 역할 수락 여부는 팀 확인 후 기입한다. 실제 API 수집·품질 집계와 검증 도구의 오프라인 테스트는 수행했다. 사용자 기능의 구현·시스템 테스트와 문서 승인은 아직 완료하지 않았다.
