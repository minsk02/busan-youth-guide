## 발견하고 수정한 부분

처음 LLM 점검에서는 무료·부산진구 조건을 일반 검색 키워드로 넣는 문제가 있었다. 비용·위치 전용 필드가 없으므로 지원하지 않는 조건으로 표시하고 키워드에서 제외하는 서버 검사를 추가했다.

기간이 있는 질문에서 날짜를 생략한 사례도 있어 프롬프트의 월 해석 설명을 보완했다. 이후 준비한 4개 질문은 통과했다. 날짜 해석이 항상 맞는다고 가정하지 않고 사용자 확인 과정을 유지한다.

공공데이터의 모집 필터가 기대대로 적용되지 않아 서버에서 모집 상태를 계산한다. 수집 실패·불완전 페이지에서 이전 DB를 보존하는 예외도 확인했다.

## 재현

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests -v
.venv/Scripts/python.exe scripts/smoke_test.py
```

오프라인 테스트는 외부 요청을 하지 않는다. smoke_test.py는 실제 키·DB가 필요하고 소량의 API 비용이 발생한다.

실제 호출의 상세 결과는 [service-smoke-test.json](../data/reports/service-smoke-test.json)에 있다. 첫 점검에서 발견된 실패는 [초기 기록](../data/reports/service-smoke-test-initial.json)에 남겼다. 인증키와 개별 원본 레코드는 포함하지 않는다.

## 화면 통합 후 점검표

화면 담당자가 실행 환경과 결과를 기록한다. 아래 항목은 확인 후 체크한다.

- [ ] Chrome·Edge에서 질문 → 조건 확인 → 검색 → 상세 → 비교를 직접 실행
- [ ] 4개째 선택 제한과 페이지 이동 후 선택 유지 확인
- [ ] 키보드·좁은 화면·긴 제목·긴 대상 원문 확인
- [ ] 실제 홈페이지의 도달 가능성·신청 경로 표본 확인
- [ ] 팀 사용자 피드백과 수동 테스트 환경·결과 기록
